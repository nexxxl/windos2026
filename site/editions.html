七种装法，
同一套东西。

同一份 WebOS、同一套应用、同一种文件格式。差别只在启动链、数据根和凭据归属。 下面每个形态都标了当前状态：能装、能验收、还是只到设计；没有下载入口的，就是还不能给你。

01 / 怎么选

你现在要解决
哪个问题？

只想先试试：装 DSH 插件。要独立应用：直接下 0.6.16 的 Windows / macOS 包，或先用 Linux 版。要带走：优盘。要长期跑在服务器或低配机器上：Linux。

你的情况推荐为什么
已经在用 DSHDSH 插件版仓库地址就是安装包，模型与会话用现成的
已经在用 OctopOctop 命令版一条命令挂进左侧，卸载即还原
想要一个独立应用Windows / macOS 包不依赖宿主；已发布到 GitHub Releases（预发布）
习惯终端，机器上只有 Node 和 Chromenpm 版不用 Go 或源码；目前是本地候选
要换电脑、进机房、给别人的机器用优盘版程序、数据甚至系统跟着盘走
长期跑在服务器或低配机器Linux 版原生窗口壳，实机验收过 Mint 与 Ubuntu
想把平板变成桌面Pad 版可设为默认桌面；终端与办公没有搬进去
02 / 装进宿主

借宿主的模型，
长出自己的桌面。

不另建控制面，也不要求你再配一份模型。宿主负责模型、会话和终端，NexlOS 负责桌面。

DSH 已发布

DSH 插件版

作为插件装进 DSH 档案，侧栏出现「NexlOS 桌面」，点开占满主工作区。模型、会话、终端都用宿主已有的。

  • 版本v1.1.1-lite.0 · 8.32 MiB
  • 要求Node.js 22+ · 可加载本地 bundle 的 DSH
  • 安装把仓库地址发给 DSH，说「安装 windos2026」
  • 限制npm 包未发布；加载插件代码需要 Full access 或当次批准
安装步骤 → 仓库 ↗
OCTOP 已交付

Octop 命令版

一条命令把本机 Octop 变成 NexlOS 宿主：左侧多一个常驻入口，点开在右侧主工作区打开桌面。

  • 命令./bin/nexlos install · status · uninstall
  • 要求Node.js 22+ · 已有 ~/.octop 安装
  • 进程独立服务，只监听 127.0.0.1:8090
  • 回滚卸载即还原宿主导航与入口
安装步骤 →
03 / 独立运行

不借宿主，
自己就是一台电脑。

Go 内核加原生窗口壳，自带 WebOS 与文件工作区。同一个版本有三个平台构建，也可以从终端启动。

WIN / MAC 已发布

Windows / macOS 包

解压即用的独立应用：本地 HTTP 服务、命令路由、文件工作区与内嵌桌面都由自己提供。

  • 版本0.6.16 · Windows x64 / Intel Mac / M 系列 Mac
  • 内核Go 0.6.16 + 原生窗口壳
  • 签名Mac 仅本地 ad-hoc 签名；Windows 未做发行签名
  • 状态三份 ZIP 已发布到 GitHub Releases（Pre-release）
下载 0.6.16 ↗
NPM 本地候选

npm 版

终端里启动编译好的内核，在 Chrome 使用本机桌面。不用 Go、Python 或下载核心源码。

  • 版本0.6.16 · 三平台包
  • 要求Node.js 22.19+ · Chrome · macOS 12+
  • 架构按 Node 进程架构选包；Rosetta 下的 x64 Node 会选 Intel 包
  • 状态npm 包尚未发布；当前用本地包安装
安装入口 →
04 / 随身携带

三档优盘，
三种能带走的东西。

三档不是三个产品，是三种边界：伞兵只带程序，随身带程序和数据，安全模式连系统一起带。Core 与应用三档共用。

≤ 1 GB 已交付

伞兵优盘

程序随盘，资料留在宿主桌面的 nexlos工作区。适合环境好、有网、可以随时生成和删除工作区的机器。

  • 版本0.2.6-key-preview.33
  • 验证Windows x64 与 macOS Intel 实机通过
  • 启动用宿主系统，不引导自己的系统
~ 128 GB 原型

随身优盘

程序和数据都随盘，加密仓库保存工作区。换一台电脑接着做，「我的 AI 跟着我走」。

  • 验证TU100Pro 加密仓库版已完成原型
  • 状态128 GB 标准版尚未制造
  • 启动用宿主系统
4–8 GB 设计中

安全模式优盘

优盘自带 Linux，连系统一起带走。用在宿主进不去、不能装软件，或需要一个干净临时环境的时候。

  • 数据随盘，持久化分区
  • 启动引导优盘里的 Linux
  • 状态选型与设计完成，尚未做原型
05 / 原生端

桌面走系统合成器，
平板走 Android。

同样的 WebOS，换成原生壳：Linux 用 GTK4 + WebKitGTK，平板用 WebView 加一层 Android 桥。

LINUX 实机验收

Linux 版

Go 内核加 GTK4 / WebKitGTK 原生壳；桌面和浏览器页面由系统合成器直接出画，浏览器标签不走截图通道。

  • 版本0.5.4 · 低配渲染档 + 语言包按需加载
  • 验收Mint 21.3 amd64 实机；无影 Ubuntu 22.04 实例
  • 未验收arm64、容器与 AI 全链路
  • 内置应用17 个；OreVein 已从内核与界面移除
ANDROID debug APK

Pad 版

全屏 WebView 承载原有外壳，Android 侧补上应用抽屉、文件导入导出和系统浏览；可设为默认桌面。

  • 设备Pixel C · Android 9 / 11 · minSdk 25
  • 已有此电脑、书房、画板、记忆、蜂群、扫雷、设置等
  • 未搬入终端、Agent 任务、办公套件、应用商店、自带浏览器内核
  • 状态debug APK；未做发行签名与商店上架

下载后核对

把 ZIP 和 SHA256SUMS 放进同一个目录，再跑对应平台的那一条。输出必须是 OK，出现 FAILED 就删掉重下。

macOS / Linux
shasum -a 256 -c SHA256SUMS
Windows · PowerShell
Get-FileHash -Algorithm SHA256 .\NexlOS-0.6.16-windows-amd64-candidate.zip

第一次打开

这一批是未公证、未做发行签名的构建，系统会拦一次。拦截不是打包出错，是签名状态如实反映在系统里。

macOS 应用只有本地 ad-hoc 签名，没有开发者 ID 与公证。第一次打开请在 Finder 里右键 → 打开；仍然被拦时执行 xattr -d com.apple.quarantine 再打开。
Windows PE 产物没有 Authenticode 签名，SmartScreen 会提示未知发布者。选「更多信息」→「仍要运行」；企业策略禁用侧载的机器上，请让管理员走白名单。

更新怎么走

独立运行的应用会读固定预发布页上的签名清单：先用编译进二进制的公钥验签，再解析清单，任何一步失败都保持当前版本。 发行公钥指纹是 ed25519:a8dcfdce0dafbc50，可以在应用的状态接口里核对。

更新清单放在固定的 update-feed 预发布页；检查失败会按 24 小时退避，并保持当前版本。
