0. 先确认

windos2026 是一个 DSH 插件，也可以作为 Octop 的桌面服务运行。它不自带模型，也不发布 npm 包；仓库本身就是安装包。

项目要求
DSH 宿主可加载本地 bundle 的 DeepSeek Harness，含 Web、会话与终端服务
Node.js22 或更高
pnpm使用 dsh plugin add 时需要 12+
权限安装 bundle 会加载插件代码，需要 Full access 或当次批准
模型不用另配；读当前 DSH 档案的模型。看不到模型时返回 501 并说明原因
平台macOS / Linux 有安装脚本；Windows 路径按 alpha 对待
安装包7.95 MiB；npm 尚未发布，npm install @nexlos/os 会 404
不需要 不需要 npm install，不需要另装模型，也不需要创建账号。安装脚本只写 DSH profile 的依赖与链接，不碰用户数据目录。

1. 方式 A：在 DSH 对话里安装（推荐）

把仓库地址发给 DSH，再说一句「安装 windos2026」。DSH 会克隆仓库，再用 plugin_manager install_bundle 把仓库目录装进当前档案。

DSH · 安装提示
# 把仓库地址发给 DSH https://github.com/nexxxl/windos2026 # 然后说 安装 windos2026

装完会发生什么

  • 仓库被克隆到 DSH 的工作目录。
  • 当前 profile 的依赖里出现 @nexlos/os，bundle 行为名是 nexlos-os。
  • 重新进入 Web 桌面后，侧栏多一个「NexlOS 桌面」入口。
  • 首次进入先显示 hello 引导，选好界面语言再进系统。
需要批准 安装 bundle 会在宿主里加载插件代码。DSH 需要 Full access，或在当次安装时明确批准。不要在应用变更时强行关闭程序。

2. 方式 B：插件管理会话

已经克隆到本地，或想指定一个固定目录时，在 DSH 的插件管理会话里执行：

plugin_manager
plugin_manager install_bundle target=/absolute/path/to/windos2026

target 指向仓库根目录，也就是包含 package.json 与 cordis.patch.yml 的那一层。装好后同样重新进入 Web 桌面。

3. 方式 C：安装脚本

不经过会话，直接把插件装进本机 profile。脚本做四件事：校验来源 → 复制插件 → 写 link: 依赖 → 建符号链接或 junction。

macOS / Linux
git clone https://github.com/nexxxl/windos2026.git cd windos2026 ./scripts/install-posix.sh # 指定档案 ./scripts/install-posix.sh --profile nexl
Windows
powershell -ExecutionPolicy Bypass -File scripts\install-windows.ps1 # 指定档案 powershell -ExecutionPolicy Bypass -File scripts\install-windows.ps1 -Profile nexlwin
脚本参数作用
install-posix.sh--profile <name>指定 DSH 档案；不给时从运行中的 dsh 进程读取
install-posix.sh--target <dir>复制位置，默认 ~/nexl/plugin
install-posix.sh--uninstall摘掉依赖与链接，保留插件文件
install-windows.ps1-Profile <name>指定档案
install-windows.ps1-Target <dir>复制位置，默认 %USERPROFILE%\nexl\plugin
install-windows.ps1-Uninstall摘掉依赖与 junction
install-windows.ps1-Restart安装后尝试重启宿主

两个脚本都跟随 DSH_HOME；自定义了 DSH home 的机器不会装到 ~/.dsh。脚本不运行 npm install，也不改 config.home 指向的用户数据。

4. Octop 工作台

Octop 不能加载 DSH bundle：它没有 Cordis 运行时，插件 API 也没有导航插槽。所以 Octop 走另一条路——把同一个 webos/ 与 index.js 作为独立 Node 服务运行，再往 Dashboard 注入一个入口。

要求

  • Node.js 22+，与 Octop 在同一台机器。
  • ~/.octop 下已有 Octop 安装（macOS / Linux；Windows 未测试）。
  • 仓库依赖：npm ci，或让安装器执行 npm install。
Octop
git clone https://github.com/nexxxl/windos2026.git cd windos2026 ./bin/octop-install install

install 会做四件事：

  1. host/octop/entry.js 会被复制到 Octop 的 dashboard/nexlos-entry.js。
  2. 往 dashboard 的 index.html 追加一个 <script> 标签；原文件保留为 index.html.nexlos-backup。
  3. 写入并启动每用户服务（macOS 是 com.nexlos.octop-desktop，Linux 是 nexlos-octop.service）。
  4. 打开 Octop。

成功后，左侧出现常驻的「NexlOS 桌面」；点开占满主工作区，命令栏用你的 Octop agent，模型指示显示 octop · <model>。

管理命令

命令作用
./bin/octop-install install注入入口，注册并启动服务
./bin/octop-install status查看服务健康、launchd 状态、Octop、注入与备份
./bin/octop-install up确保服务在跑，然后打开 Octop
./bin/octop-install down停掉桌面服务，保留入口
./bin/octop-install uninstall还原 index.html，移除入口与服务
./bin/octop-install doctor检查 Node、依赖、webos/、Octop venv 与端口

环境变量

变量默认值作用
NEXLOS_PORT8090桌面服务端口
NEXLOS_HOME与 DSH 版共享应用与数据目录
OCTOP_URLhttp://127.0.0.1:8088Octop 地址
NEXLOS_BIND127.0.0.1绑定地址；默认只回环
NEXLOS_STATE_DIR~/.nexlos-octop配置与日志

两种宿主差在哪

区域DSHOctop
启动宿主里的插件 bundleDashboard 入口背后的独立 Node 服务
模型当前 DSH 档案你的 Octop agent
终端可用（宿主 PTY）不可用：独立宿主没有 PTY，term.info 返回 enabled:false 与原因
会话工具 / 子代理 / 浏览器桥由 DSH 提供不在；相关命令返回 501 与原因
文件、应用、命令、主题、语言相同相同
已知限制 入口是 DOM 注入，不是官方导航插槽。Octop 升级重置 index.html 后，重新运行 ./bin/octop-install install。桥只读 ~/.octop/credential.txt 的管理员账号，按单用户使用；端口只监听回环，不要对外暴露。

回滚：./bin/octop-install uninstall。卸载会还原 Dashboard、移除服务，但不会删除 NexlOS home 里的应用。宿主差异与更多限制见 docs/octop.md。

5. 第一次进入

重新进入 Web 桌面后，首次会先显示 hello 引导：黑底大字招呼语、语言选择，然后进系统。选择结果写入 settings.json → language。

  • 想重看引导：在地址后加 ?hello=1。
  • 之后修改：设置 → 时间和语言。
  • 数据目录：config.home 优先；否则 NEXLOS_HOME；否则已存在的 ~/Library/Application Support/NexlOS；最后落到宿主工作目录下的 spaces/。

6. 可选包

主包带 8 种内置语言、两套主题、两张壁纸和一段背景音乐。画板、7 种扩展语言和 CJK 办公字体在可选包里，按需安装。

可选包
# 画板（ArtCraft 移植版） ./scripts/install-extras.sh artcraftport # 7 种扩展语言 ./scripts/install-extras.sh langs # CJK 办公字体：公开仓不携带，需先放到 extras/fonts-cjk/ ./scripts/install-extras.sh fonts

脚本把资源放到 webos/extras/ 或 webos/a/office/fonts/，运行时按路径取用。公开仓不带 CJK 字体包；直接运行 all 会在字体这一步停下，先装 artcraftport 与 langs 即可。

CDN 可选 如果你的部署把 extras 放到 CDN，可以在加载 app.js 之前设置 window.NEXLOS_PACKS_BASE，语言包与画板都从前缀取。主包不依赖这个设置。

7. 核对

  • DSH 侧栏出现「NexlOS 桌面」，点开能进桌面。
  • 首次进入出现 hello 引导；选完语言后界面文案跟着变。
  • 设置 → 应用 能看到 17 个内置应用；「系统」不在桌面与 Dock。
  • 打开「系统」，能看到 25 条命令与插件版本 1.1.0-lite.0。
  • 打开「应用生成」，能写出一句话并生成一个内嵌应用（需要模型）。
  • Octop：./bin/octop-install status 正常；curl -s http://127.0.0.1:8090/agent/status 返回 "provider":"octop"。

开发侧核对：

开发侧
npm ci npm run check npm test ./scripts/verify-lite.sh npm pack --dry-run --json

verify-lite.sh 检查 tarball ≤ 10 MB、包内不含语言覆盖层与 CJK 字体、画板资源在 extras/、媒体为 AAC、壁纸存在。

8. 卸载

卸载只摘依赖与链接，不删除你的应用与工作区。

卸载
# macOS / Linux ./scripts/install-posix.sh --uninstall # Windows powershell -ExecutionPolicy Bypass -File scripts\install-windows.ps1 -Uninstall # Octop ./bin/octop-install uninstall

也可以在 DSH 的插件管理里移除 @nexlos/os bundle。应用仍在 NexlOS home 的 apps/ 下；需要保留时先复制这个目录。

9. 故障排查

现象原因处理
npm install @nexlos/os 404npm 尚未发布用仓库地址或安装脚本
装完没有 NexlOS 入口没有批准 Full access，或 profile 未写入 bundle检查 profile 依赖与 dsh.profile.bundles；完全退出宿主再进
模型状态 unavailable / 能力返回 501宿主档案里没有可用模型在 DSH 里配置模型与凭据；插件不带 key
画板显示「未安装」可选包没装./scripts/install-extras.sh artcraftport
扩展语言不在选择器里语言包没装./scripts/install-extras.sh langs，重载桌面
中文办公行高与分页不同没有 CJK 字体包，回退系统字体安装 OFL 字体包，或接受系统字体回退
Octop 升级后入口消失Dashboard 的 index.html 被重置重跑 ./bin/octop-install install
Octop 里终端不可用独立宿主没有 PTY用 DSH；Octop 的 term.info 会说明原因
Octop 端口冲突8090 被占用NEXLOS_PORT=8091 ./bin/octop-install up
Windows 上行为异常Windows 路径按 alpha 对待提 issue，附版本、路径与日志

10. 其他形态

本页讲的是 DSH 与 Octop 两种宿主装法。其他形态的入口、状态与限制见 版本；下面是最短路径。

形态怎么装状态
Windows / macOS 包下载对应 ZIP，解压运行；目前没有公开下载本地候选 0.6.15
npm 版进入包目录用 nexlos 启动；npm 包尚未发布本地候选 0.6.15
优盘版按盘内说明运行；伞兵版已交付，随身与安全模式未发行已交付 / 原型 / 设计
Linux 版按 Linux 文档在 amd64 上原生安装实机验收 0.5.4
Pad 版安装 debug APK，可在系统设置里设为默认桌面debug APK

没有公开下载入口的形态，就是还不能给；不要从第三方转载包安装。
