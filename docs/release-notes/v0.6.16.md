# NexlOS 0.6.16

NexlOS is a self-contained AI-native desktop: its own window shell, the desktop
layer you can read in the plugin edition, and an updater that verifies a signed
manifest. This release is the **universal edition** — no Node.js, no DSH, no
Octop. Download, unzip, run.

0.6.16 is the 便携办公 (office) release. Opening a Word file now keeps the
document's real table grid, merged cells, borders, shading, cell padding,
repeating header rows, theme fonts, character-based indents and page setup.
Word and PDF both zoom, and PDF pages render through pdf.js on canvas instead
of an iframe that could not scale. The plugin edition gets the same viewer, with
its own zero-dependency DOCX reader.

## What changed in 便携办公

- **Tables.** The DOCX reader now reads `tblGrid` and `tblW`, `gridSpan`,
  `vMerge`, `tblBorders`, `tcBorders`, `shd`, `vAlign`, `tblCellMar` and
  `tblHeader`, so a form keeps its column widths, merged cells, rules, shading
  and repeated header row.
- **Text.** `styles.xml` `docDefaults` and `theme1.xml` fonts are applied,
  including East Asian theme fonts; `w:ind` honours `leftChars` and
  `firstLineChars`, and `w:spacing` keeps before/after/line values.
- **Page.** Page size, orientation and margins come from `w:sectPr`, so A4
  landscape forms are no longer rendered as portrait A4.
- **Zoom.** A `150%` preset and fit-to-width scale the page box itself, so text,
  tables and images grow together. Trackpad and `Ctrl`+wheel work on both Word
  and PDF.
- **PDF.** Pages render through a vendored pdf.js 3.11 (Apache-2.0) build:
  canvas per page, lazy rendering, print from the canvases. The page counter now
  reads the count pdf.js reports; the old byte scan missed PDFs with object
  streams and always showed one page.

The plugin edition (`@nexlos/os`) ships the same viewer and reads DOCX through a
new zero-dependency module, `src/office-docx.js`.

## Upgrade

Apps update from the signed manifest on the `update-feed` release. The feed
carries this batch's three archives; an existing 0.6.15 install can verify and
switch versions without downloading manually. Manual installs follow the same
steps as 0.6.15:

**macOS** — swap `arm64` for `amd64` on an Intel Mac:

```sh
TAG=v0.6.16
gh release download "$TAG" -R nexxxl/windos2026 -p '*darwin-arm64*.zip'
unzip -q NexlOS-*-darwin-arm64-candidate.zip -d /tmp/nexlos
mv /tmp/nexlos/NexlOS-*/NexlOS.app /Applications/
```

**Windows (PowerShell, x64):**

```powershell
$tag = "v0.6.16"
gh release download $tag -R nexxxl/windos2026 -p '*windows-amd64*.zip'
Expand-Archive .\NexlOS-*-windows-amd64-candidate.zip -DestinationPath .\nexlos
.\nexlos\NexlOS-0.6.16-windows-amd64-candidate\nexlos.exe
```

Verify before running:

```sh
shasum -a 256 -c SHA256SUMS
```

## Known limits

- **Windows and Apple Silicon are still pending real-device acceptance.** The
  Windows candidate is cross-built with the pinned prebuilt shell; the
  Apple Silicon binary is cross-compiled on an Intel host and never launched
  here. macOS binaries carry ad-hoc signatures; Windows carries no Authenticode
  signature.
- **SEC-001 is open.** `open.url` reaches the Windows shell through `cmd /c
  start`, so a link containing `&` can start a second command. The fix needs a
  Windows host to verify and is scheduled for the next release. Until then, do
  not open untrusted links through 便捷办公 on Windows.
- **No obfuscation in this batch.** The build runs without garble, as 0.6.15 did.
- The plugin tarball is still not on npm (`@nexlos/os` returns 404). Install it
  from the repository with `install_bundle`, as described in the README.
